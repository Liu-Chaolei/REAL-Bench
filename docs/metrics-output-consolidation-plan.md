# 指标输出收拢与及时响应规则整理计划

状态：已实施。本次只完成四项输出／规则整理；其他并行工作及暂缓指标保持各自范围。

关联文档：[指标清单](metrics-inventory.md)、[语音交互指标合并计划](voice-interaction-metrics-unification-plan.md)。

## 1. 本次范围

| 修改项 | 已确认决定 |
| --- | --- |
| 整题 `reward` | 取消独立性能指标，保留 `ENV_ASSERTION`，避免同一结果重复展示 |
| 后台任务评分 | 只保留一个“后台请求完成分”；后台结果与回复判断改为明细 |
| `on_time_rate` | 取消有工具／无工具双阈值，首次响应统一使用一个及时阈值 |
| 通话级 `selectivity` | 删除错误次数超过 3 次的独立标记，保留三项细化指标 |

本次不处理以下事项：

- 新增统一整体完成指标。
- `avg_reward`、`pass^1`、`pass^k` 的保留、命名或公式调整。
- 持续发声算 0 秒响应、咳嗽回应的时间归属等尚未定案的问题。
- `effective_interaction_rate`、Progressivity、Grounding 的取舍与合并。
- Grounding 与精简反馈事实判断的共用或合并。
- `raw_feedback_score`、`feedback_score`、`material_error_rate` 的输出取舍。
- 另一个 Agent 正在处理的参考答案、参考操作、依赖和数据质量问题。

实施时保留其他 Agent 的工作区修改，不整文件覆盖，不顺手重做它们负责的规则。

## 2. 实现原则

主要通过数据来源和输出机制保证一致性：

1. 环境分读取明确的环境评分结果，不重新计算。
2. 后台请求完成分只计算一次，分项判断作为随附明细。
3. 及时率只依赖响应延迟和单一阈值。
4. 已删除的通话标记从生成源头移除。

不增加评测前验收、逐轮校验、双版本对照、评分后审计或自动重跑流程。不为本次整理调用额外模型、扩大数据集测试或重评分历史结果。

## 3. 整题 reward：保留环境结果，取消重复性能输出

### 3.1 当前依赖

正常 Gaia2 路径下，整题 reward 与 ENV Assertion 相同。但 `reward_info.reward` 也是 τ-bench 的共用字段，仍被轨迹保存、`avg_reward`、`pass^k` 和其他领域使用。

本轮不直接删除这个底层字段，避免牵连尚未决定调整的指标。删除的是 Gaia2 面向用户的独立整题 Reward 指标和重复展示。

### 3.2 唯一来源

- Gaia2 单次环境结果读取 `reward_breakdown[ENV_ASSERTION]`。
- 展示名称统一为 `ENV_ASSERTION`；需要结构化输出时建议使用明确的 `env_assertion` 字段。
- 去掉同一结果中重复的单独 Reward 行。
- 原轨迹 `reward_info.reward` 暂留为框架兼容字段，不再解释成另一项性能。
- 环境条件和状态比较公式保持当前含义。

不能把任意 reward 直接改名为 ENV Assertion。其他领域和历史组合奖励可能包含不同分项，必须读取明确记录的环境分。

没有环境分、评分失败或尚未评分时，使用已有不可用状态；不把默认值、缺失值或组合奖励充当环境通过结果。

### 3.3 展示及兼容

覆盖终端单次结果、轨迹查看、Markdown 导出及相关能力输出。原始轨迹允许继续携带兼容字段，完整原始 JSON 不等于性能面板。

`avg_reward` 和 `pass^k` 的字段、计算和输出本次保留。其他领域的任务奖励也不因 Gaia2 的展示整理被改名或删去。

预计入口：

- `src/tau2/utils/display.py`：消除 Gaia2 单次 Reward 与环境分的重复展示。
- 相关结果收集、报告及导出入口：传递明确环境分。
- `src/tau2/evaluator/`：仅在必要时整理字段传递，不重定义环境判断。
- 指标清单与说明：解释框架兼容字段与性能指标的区别。

## 4. 后台任务：一个完成分，两个判断明细

### 4.1 主指标

建议字段统一为：

```text
persistent_task.completion_score
```

显示名称为“后台请求完成分”。这只是本轮提出的明确字段命名，不新增评分维度。

沿用现有总分含义：后台管理操作取得符合要求的结果，并且回复满足当前判断要求，完成分才为 1；可明确评分的失败为 0，既有不可用情况为 null。

本次不改变动态请求与旧固定请求各自的成功条件，不重新设计查询、结果获取、修改、取消的判断，也不调整回复窗口。

### 4.2 输出结构

建议单次结果形状：

```json
{
  "status": "measured",
  "completion_score": 1,
  "evaluation_log": {
    "native_result": {"passed": true},
    "reply": {"passed": true}
  }
}
```

具体操作、状态、实际返回、回复文本、请求 ID、裁判理由等继续保留在明细中。实际字段复用已有数据，避免重复保存大段证据。

修改要求：

- 主性能输出移除 `native_result_reward`、`reply_reward` 和原 `persistent_task.reward`。
- 后台结果和回复分项转为通过／未通过／不可用的明细。
- 复用已有判断来生成完成分，不再运行一次模型或判断链。
- 操作判断没有通过、因而跳过回复裁判时，明细应如实说明未独立评价回复，不能误写成“模型认定回复错误”。
- `operation_reward` 等已有操作信息继续归入日志，不新增性能分。
- 汇总只输出 `completion_score`；同题试验先平均，再对题等权。

### 4.3 动态与旧固定路径

动态请求和旧固定请求内部条件不同，本次只统一对外结果结构，不将某一路径的条件强行搬到另一路径。

旧记录读取顺序：

1. 新字段 `completion_score`。
2. 原后台总分 `reward`。
3. 更早记录中的后台总分兼容字段 `native_reward`。

读取必须保留 0 和 null 的区别，不使用会跳过 0 的真假值回退。不根据旧明细重新计算并覆盖历史总分。

旧分项 `native_result_reward`、`state_result_reward`、`reply_reward` 只转换为明细，不重新在能力面板展示。

仍然使用显式后台组合奖励的调用方，通过一个小型读取函数获取完成分；不让各处自行猜字段名。本次不更改组合奖励开关及其既有含义。

预计入口：

- `src/tau2/metrics/active/persistent_task/runtime.py`
- `src/tau2/evaluator/persistent_tasks/grader.py`
- 必要的旧固定请求和历史读取兼容代码
- `src/tau2/evaluator/outcome.py` 及其他确实读取后台总分的调用方
- `src/tau2/diagnostics/suite.py`
- 对应配置说明、显示和导出

## 5. On Time Rate：统一及时阈值

### 5.1 已确认与建议参数

已确认的是取消工具调用区分，使用一个统一阈值。

实施时采用计划建议的 **2.75 秒**作为统一默认值，集中在 `VOICE_INTERACTION_CONFIG.on_time_sec`。用户已授权按计划实施；这个值是本轮采用的默认参数，不表述为更早逐项讨论时就已确认的数值。

阈值集中保存在一处配置，后续调整数值不需要修改计算流程。

### 5.2 计算方式

```text
on_time_rate
    = 延迟小于统一阈值的已响应次数 / 已响应次数
```

- 使用严格的小于；恰好等于阈值不算及时。
- 0 秒响应仍算及时。
- 未响应不进入分母，继续由 response_rate 体现。
- 没有已响应样本时为 null。
- 复用当前统一响应记录，不新建一套响应匹配。

### 5.3 删除工具上下文依赖

- 保留一个 `on_time_sec`。
- 从新口径配置移除 `on_time_tool_sec`。
- 删除依据 `has_tools` 选择 2.75／4 秒的分支。
- 删除“缺少工具上下文就无法判断及时性”的前置条件。
- 只要响应延迟可用，就能判断及时性。
- 工具记录继续服务其他用途，但不参与及时率计算。

不改变正式发言分类、持续发声的 0 秒规则、响应观察范围、response_rate、平均延迟或 P90。

### 5.4 版本与历史

阈值口径变化会影响数值，因此更新语音指标版本与配置说明。新旧及时率不混为同一口径汇总。

历史记录保留原工具阈值和版本信息，不自动重写或批量重评分。已有版本分组／读取路径做必要调整即可，不新增运行时双版本核验。

预计入口：

- `src/tau2/config.py`
- `src/tau2/metrics/voice_interaction.py`
- 语音诊断汇总、排行榜和导出中的版本引用
- `docs/interaction-metrics.md` 等当前规则说明

## 6. 删除通话级 selectivity 标记

### 6.1 删除对象

删除以下规则及其派生性能输出：

```text
三类 selectivity 错误次数合计超过 3 次
    → 通话 selectivity 标记为 1
```

三项细化指标保留：

```text
selectivity_backchannel
selectivity_vocal_tic
selectivity_non_directed
```

### 6.2 源头与出口一起整理

- 删除 `SELECTIVITY_ERRORS = 3` 及通话标记计算。
- 新结果不生成通话级 `selectivity: 0/1`。
- 汇总不计算“被标记通话比例”。
- 质量报表、对应导出 schema 和显示入口移除该字段。
- 三项正确率及其事件、正确／错误次数继续保留。
- 只为计算这个标记存在的调用链可以移除，不为它继续运行语音测量。

当前 benchmark_quality 路径中，这个标记是剩余的主要通话性能项。删除后：仍有用途的运行日志保留；不再制造空的通话质量总分或空性能块。

读取历史记录时可以容忍旧标记，但新面板不自动恢复展示它。

### 6.3 避免误删同名内容

必须区分：

1. 三项细化 selectivity 正确率。
2. 某些旧展示中对三项取平均的内容。
3. 本次删除的“超过 3 次错误”通话标记。

本轮只删除第 3 种，不做全局名称替换，也不顺手调整第 2 种的定义。

预计入口：

- `src/tau2/metrics/call_quality.py`
- `src/tau2/scripts/leaderboard/benchmark_quality.py`
- 对应 schema 生成与展示入口
- `src/tau2/metrics/interaction_quality.py` 中仅服务该标记的调用链

共享能力仍有其他调用者时保留，避免为删一个标记扩大成语音模块重写。

## 8. 轻量验证

优先调整已有相关测试，必要时补少量有实际含义的例子。

### ENV 展示

- 环境分只展示一次。
- 旧组合 reward 不被直接标成 ENV Assertion。
- 缺失环境结果保留不可用。
- `avg_reward`、`pass^k` 仍能读取原兼容字段，不改变计算含义。

### 后台完成分

- 成功、后台结果失败、回复失败和不可用各一个样例。
- 主面板只有 completion_score，两个分项保留在明细。
- 旧记录可读取，0 与 null 不混淆，不重新调用裁判。
- 现有显式组合奖励能够取得同一个完成分。

### 及时率

- 相同响应延迟在有工具、无工具、缺少工具日志时结果一致。
- 阈值前、恰好阈值、阈值后各一个样例。
- 0 秒响应和未响应仍符合现有定义。
- 新旧版本不混算。

### Selectivity

- 新报告中没有通话级标记及其比例。
- 三项细化正确率和对应明细保留。
- 导出数据模型和生成的 schema 与新结构一致。

完成相关本地测试、Ruff 与差异格式检查即可。不调用真实模型 API，不要求完整数据集评测，不全量重评分历史文件，不建立新的验收脚本。
