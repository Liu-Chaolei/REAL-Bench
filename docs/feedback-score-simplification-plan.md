# 精简反馈指标收拢实施计划

状态：已实施。当前反馈版本为 `tau-feedback-conciseness/2`；本文件保留讨论决定与实施步骤，完成记录见末节。

## 1. 目标和范围

精简反馈模块只评价必要信息是否正确覆盖、表达是否精简，并输出一个综合分。陈述真实性由 Grounding 负责。

已确认的决定：

1. 合并 `raw_feedback_score` 与 `feedback_score`，保留一个反馈综合分。
2. 删除独立的 `fidelity_status` 判断及重大事实错误清零规则。
3. 删除 `material_error_rate`。
4. 必要信息说错仍不算正确覆盖，但不再因此把整个反馈综合分强制归零。

本计划保留字段名 `feedback_score`，使现有展示入口改动较小。Grounding 的分数或判断不再接回反馈公式，两项可以独立计算。

之前暂缓讨论的整题 reward、后台请求完成分、On Time Rate 阈值、通话级 selectivity 等，不纳入本次改动。参考答案审查和状态管理机制的其他工作也不属于本次范围。

## 2. 最终输出

| 内容 | 处理 |
| --- | --- |
| `required_coverage` | 保留：必要信息正确覆盖率 |
| `length_efficiency` | 保留：表达长度效率 |
| `feedback_score` | 保留：直接由覆盖率和长度效率计算 |
| `raw_feedback_score` 及其上下界 | 删除重复输出 |
| `fidelity_status`、`fidelity_reason` | 从反馈模块删除 |
| `material_error_rate` | 删除辅助统计 |
| `material_error_windows` | 删除关联计数 |
| 重大错误判断与反馈分清零 | 删除 |

计数、长度、预算、匹配解释、适用范围和缺失原因继续放在日志或明细。分数上下界仅表达信息匹配不确定性，不作为额外性能指标。

## 3. 评分公式

设 R 为必要信息覆盖率，E 为长度效率：

```text
feedback_score = 100 × 10 × R × E / (9 × E + R)
```

R、E 都为 0 时返回 0。范围为 0～100，保留现有偏重覆盖完整性的 F3 公式。

长度预算、字符计数、必要和可选信息点的去重规则保持当前定义。本次不调整预算参数、不新增语言校准、不重新拟合预算。

### 3.1 正确覆盖与事实判断的边界

反馈模块仍需判断一个固定信息点是否被正确表达：对象、数值、单位、条件、时间和确定程度不符，不能计作已覆盖。

它不再扫描整段回复并单独裁定重大事实错误，不再因某个错误给整段反馈分清零。

例一：三个必要信息点中两项正确、一项错误。

```text
required_coverage = 2 / 3
feedback_score = 用该覆盖率与长度效率正常计算
```

例二：三个必要信息点均正确，但额外编造了一条业务事实。

- 必要信息覆盖率可以为 1。
- 额外文字仍计入实际长度，可能影响长度效率。
- 编造内容的事实评价由 Grounding 负责。
- 反馈分不再触发额外的整段清零。

## 4. 模型流程调整

保留现有两个阶段：

```text
实际用户要求和执行证据
        ↓
生成并固定必要／可选信息清单
        ↓
核对实际回复是否覆盖这些信息
        ↓
程序计算覆盖率、长度效率、反馈综合分
```

第一阶段继续不提供当前待测 Agent 回复，防止根据实际回复倒推评分清单。不因本次删除真实性判断而改用 Agent 的额外声明建立业务事实。

第二阶段提示词收拢为信息点匹配和表达明细：

- 删除整体真实性评价要求。
- 删除 `fidelity_status`、`fidelity_reason` 输出要求。
- 删除扫描重大错误、错误清零及“纠正后仍保留清零处罚”等要求。
- 保留逐项匹配、原文引用、语义范围和必要时间判断。
- 重复、无关内容只用于解释表达，不触发事实错误处罚。

信息点匹配状态继续保留：

| 状态 | 用途 |
| --- | --- |
| `matched` | 信息被正确表达，计覆盖 |
| `missing` | 缺失或实质不完整，不计覆盖 |
| `contradicted` | 对应信息说错，不计覆盖 |
| `uncertain` | 无法可靠判断，保留未知范围 |

`contradicted` 只影响该项覆盖，不自动升级为整个窗口的重大错误。

对于先错后明确纠正的回复，覆盖判断继续看最终明确立场；未解决的冲突不能通过挑选有利句子来计覆盖。对先前错误的独立真实性评价交给 Grounding。

## 5. 模型输出结构和处理代码

### 5.1 `conciseness/models.py`

- 从 `Alignment` 删除 `fidelity_status` 和 `fidelity_reason`。
- 从 `Finding` 删除 `material_error` 类型。
- 保留匹配项，以及重复、无关内容及无法确定的表达明细。
- 修改相关说明，避免仍要求模型评价整体事实正确性。

### 5.2 `conciseness/evaluator.py`

- 删除将 `contradicted` 自动生成重大错误 finding 的逻辑。
- 删除重大错误引用的专用处理。
- 删除根据 findings 或匹配状态合成 `fidelity_status` 的代码。
- 无回复时只生成各信息点的 `missing`，不再补出“真实性通过”状态。
- 评测结果的完整性由信息清单和匹配是否可用决定，不再受独立真实性判断影响。

已有的信息点 ID、原文引用和必要时间处理按原用途保留。本次不扩展校验范围，不增加额外模型复核、事实裁判或验收模块。

## 6. 唯一综合分的计算

在 `conciseness/scoring.py` 中：

1. `_point()` 直接输出 `feedback_score`。
2. 删除对 `fidelity_status` 的读取。
3. 删除重大错误清零分支。
4. 删除真实性未知时把反馈分下界改为 0 的分支。
5. 删除所有新的 `raw_feedback_score` 输出及上下界字段。
6. 保留 `feedback_score_lower`、`feedback_score_upper`，仅表示信息匹配不确定带来的范围。

### 6.1 缺失和未知

- 必要信息匹配未知：保留分母，覆盖率可能为空，同时输出上下界。
- 可选信息匹配未知：长度预算、长度效率或综合分可能出现范围。
- 信息匹配存在未知时，某个分项若上下界恰好一致，可以沿用现有机制输出确定值；不人为扩大未知影响。
- 没有适用语言的长度预算：覆盖率可独立计算，长度效率和综合分为空。
- 信息清单和预算可靠但没有回复：覆盖率、长度效率和综合分为 0。
- 整个窗口不需要反馈：按现有不适用规则处理。

不再因为固定信息清单之外的事实无法核实，就让整段反馈综合分变为空。

## 7. 跨窗口历史信息

当前代码只有在 `fidelity_status == supported` 时，才把已匹配的信息写入后续窗口历史。删除该字段时必须一起调整，不能直接删除条件后把全部内容放进去。

新机制：只传递明确正确覆盖的信息组。

1. 继续按已有 `equivalence_group` 去重。
2. 只有组内匹配结论明确一致为 `matched`，才进入历史。
3. `missing`、`contradicted`、`uncertain` 以及组内结论冲突的内容不进入。
4. 传递固定信息清单中的命题、来源和窗口身份，不复制 Agent 未经核实的额外声明。
5. 历史含义是“这条信息之前已经交付”，不自动表示业务事实永远有效。
6. 后续用户明确要求重复说明时，历史记录不能免除这次反馈义务。

通过固定清单和已匹配等价组决定历史来源，不增加“历史可信度裁判”，也不依赖 Grounding 是否已经运行。

## 8. 窗口、单次测试与总汇总

各层新输出统一只包含三个能力指标：

```text
required_coverage
length_efficiency
feedback_score
```

需要同步的地方：

- 每个反馈窗口结果。
- `trial_summary()` 的单次结果。
- `aggregate_reports()` 辅助汇总。
- `diagnostics/suite.py` 主汇总。
- 显示、CLI 导出及其他直接消费这些字段的位置。

`material_error_rate` 所在的辅助汇总虽未接入主流程，仍删除其计算以及 `material_error_windows`，避免将来重新使用该函数时恢复已取消的字段。

保留现有汇总顺序：

1. 各窗口独立计算 F3。
2. 单次测试内适用窗口等权平均。
3. 同一道题的多次适用试验先平均。
4. 不同题目等权平均。

不先平均覆盖率和长度效率再代入 F3。适用窗口存在不可评分情况时，沿用既有处理，不在这次重新制定整体不可评分政策。

## 9. 版本与历史结果

旧 `feedback_score` 包含重大错误清零，新分数没有这一层；必须保留版本差异，不能仅因同名而混算。

- 精简反馈版本升级，例如从 `tau-feedback-conciseness/1` 到 `/2`。
- 更新第二阶段提示和 schema 对应的缓存身份。
- 新对齐结果不复用旧真实性判决冒充新输出。
- 历史结果文件保留原版本和原数值，不原地重写。
- 汇总按反馈版本区分；旧结果展示为历史口径，不混入新综合分均值。
- 新版主输出中不再保留 raw 分作为重复字段。历史原始记录如包含旧字段，可按历史记录保留。

第一阶段信息清单定义未变，优先复用兼容的已冻结清单。实施时可使用独立清单版本或既有内容身份保持缓存兼容；不要为了复用而建设复杂迁移系统。如果旧清单无法明确复用，按现有缺失缓存流程处理，不主动批量重评。

这属于数据和结果版本管理，不增加新的运行前后验收流程。

## 11. 实施顺序

### 第一步：收拢模型职责与输出

修改 Alignment/Finding 模型和对齐提示词，去掉真实性字段及重大错误判定。保留信息点匹配状态和必要引用。

产出：新裁判输出从结构上不再承担独立真实性评分。

### 第二步：精简评分公式

将旧 raw 分的 F3 直接作为唯一 `feedback_score`，删除清零、真实性未知处罚和重复输出。保留信息匹配导致的上下界。

产出：只有覆盖和长度参与的综合分。

### 第三步：调整窗口历史

根据明确匹配的等价组传递已交付信息，去掉整个窗口的真实性开关，避免传播未知、冲突或额外声明。

产出：不依赖独立真实性判断的后续窗口上下文。

### 第四步：同步汇总与版本

删除各层 raw 分、错误窗口数和错误率统计；更新版本、缓存和必要历史分组。检查显示和导出是否仍引用旧字段。

产出：三个保留指标的统一新输出，历史口径可区分。

### 第五步：更新文档与针对性开发测试

更新当前说明，替换原有重大错误清零测试，运行相关本地测试和修改文件的格式检查。

产出：可 review 的代码改动及简短验证记录。

## 12. 轻量验证

优先改用已有测试样例，仅覆盖以下关键行为：

1. 同样的覆盖率和长度效率，唯一综合分等于原 F3 数值。
2. 必要信息说错只降低该项覆盖，不触发整段强制清零。
3. 新模型输出和新报告不再要求或生成真实性状态、raw 分或重大错误率。
4. 后续历史只包含明确匹配的信息组，未知和组内冲突不能通过挑选有利项进入。
5. 无回复、无语言预算、信息匹配未知等边界仍按既有规则工作。
6. 主汇总保留三个指标，新旧版本不会混算。

只使用本地样例、假模型输出和现有测试。无需真实模型 API、完整数据集重跑或现场验收。

不增加运行前检查、逐窗口复核、双裁判、自动重评分或新验收脚本。职责分离主要由提示词、输出 schema、单一公式和历史数据流实现。

## 13. 完成后的预期状态

反馈模块输出必要信息覆盖率、长度效率和一个 F3 综合分。独立真实性判断、重大错误清零以及重大错误率统计均移出该模块。

Grounding 独立评价陈述真实性与状态使用；反馈分不再依赖它的分数。新旧反馈版本有明确标识，历史结果保留原含义。

## 14. 实施记录

- 新版对齐模型只输出信息点匹配和表达明细，不再包含 `fidelity_status`、`fidelity_reason` 或重大错误 finding。
- `feedback_score` 直接计算原 F3，不再生成 raw 分或进行事实错误清零。必要信息的 `contradicted` 仍不计覆盖。
- 覆盖计分与历史传递共用去重等价组；只有组内明确一致为 `matched` 的清单命题及来源进入后续窗口，未知、错误或冲突组不会传递。该机制不调用 Grounding。
- 已删除各层 raw 分、重大错误窗口数和重大错误率统计；主汇总只展示覆盖率、长度效率和一个综合分。
- 评分版本升级到 `/2`，第一阶段清单缓存身份仍为 `/1`；本地样例验证可复用兼容冻结清单，第二阶段改用新提示和 schema。历史报告没有重写，主汇总和辅助汇总按反馈版本分组，`tau2 view` 显示反馈版本。
- 保留当前中文及英文预算、校准来源哈希、请求变更和其他工作区改动。没有修改 Grounding、参考答案或其他指标定义。
- 已更新当前说明与指标清单，并给旧设计文档加上历史说明。

验证：共 76 项相关本地测试通过，包括精简反馈测试、指标汇总测试和请求变更测试；覆盖公式、无回复、未知区间、去重历史、跨窗口实际传递、冻结清单复用及新旧版本分组。Ruff 检查与修改文件格式检查通过，`git diff --check` 通过。未调用真实 API、未重跑数据集、未新增评测主流程验收或检查模块。
