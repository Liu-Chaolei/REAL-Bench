# Gaia2 中立委托者用户设定：实施计划

状态：已实施。日期：2026-11-22。具体交付与离线检查结果见 [实施记录](gaia2-neutral-user-results.md)。以下保留设计与范围约定。

## 1. 唯一目标

去掉 Gaia2 用户模拟器继承的“客户打电话给客服”身份及配套客服人设，采用 ARE 的中立任务委托者角色。

角色基准来自 ARE `UserProxyLLM` 默认提示：人类用户与正在完成其委托任务的 AI Agent 交互。

来源：[ARE user_proxy.py](https://github.com/facebookresearch/meta-agents-research-environments/blob/main/are/simulation/agents/user_proxy.py)。这是通用角色起点，不是完整语音模拟实现；本项目继续使用已有语音和阶段运行机制。

此次不增加用户对工具、应用接入或账户权限的新知识，不指示用户纠正 Agent 的能力判断，不指示用户教 Agent 调工具。目标不是确保 Agent 成功，也不是让用户无条件配合。

## 2. 实现方式

在 Gaia2 用户实例构造时选择一份独立的中立提示。复用已有 `global_guidelines_override` 和语音用户的 `role_reminder_override`。

一致性通过构造方式保证：

```text
构造 Gaia2 用户
  → 选择 Gaia2 中立指南
  → 显式加入必要的任务/知识/语言规则
  → 不引入客服语用人设块
  → 语音每轮使用中立身份提醒
  → 原有用户生成与语音流程
```

不生成旧提示再按关键词删句，不在每轮生成后判断是否像客服，不添加拦截、重写、重试或额外裁判。这里新增的是角色配置和提示组装，不是评测检查步骤。

## 3. 当前会注入客服身份的位置

| 位置 | 当前内容 | 处理方式 |
|---|---|---|
| `src/tau2/user/guidelines.py` | voice/text 通用模板中的客户、客服、投诉式示例 | Gaia2 使用独立 override，不修改其他领域的通用模板 |
| `src/tau2/user/user_simulator_streaming.py` 的回复生成入口 | 每轮追加 CUSTOMER 身份提醒 | 构造 Gaia2 语音用户时传中立 reminder |
| `RuntimePersona.to_guidelines_text()` | 自动合并 gender_guidance、普通与语音 pragmatics、领域指南 | Gaia2 的 override 不使用完整 persona 插槽，显式选择需要的内容 |
| `data/tau2/multilingual/en/pack.yaml` 的人设 | customer、要求主管、反复强调、受挫时强硬等 | 不向 Gaia2 的角色提示注入这些块，不修改共享语言包 |
| 题目说明、已发布阶段请求 | 原始任务与用户已知事实 | 原样传入，不通过角色修改篡改任务内容 |

在 0760 上只替换最开始的一句话不够：它的其他人设块和每轮提醒仍然会强调客服关系。因此必须同时处理上表前三个组装入口。

## 4. 中立指南应包含的内容

建议新增 `src/tau2/user/gaia2_guidelines.py`，集中放置：

- `GAIA2_USER_GUIDELINES_VERSION`：例如 `gaia2-neutral-user-v1`。
- `GAIA2_ROLE_REMINDER`：每轮中立角色提醒。
- `get_gaia2_user_guidelines(persona, *, mode, use_tools)`：为 text/voice 生成对应提示。

它只生成字符串，不调用模型、不读取业务状态、不访问工具结果、不参与评分。

### 4.1 角色正文

建议的英文主句采用 ARE 的中立含义：

```text
You are a human user interacting with an AI agent that is trying to
complete a task you have given it.
Respond as the user, using the current request and the conversation so far.
```

语音模式再加一条短说明：通过语音交流，每次生成一句或一段自然的用户发言。文本模式使用文本交流表述。

不再强制设定为某机构的来电客户，不建立“主管、客服团队、投诉升级”的默认关系。提示不必堆叠“禁止说主管”等负面规则：从源头不注入这些预设即可。题目若明确包含这些实体，仍应遵循题目。

### 4.2 任务与知识边界

保留现有约束的含义，以中性措辞表达：

- 以当前已发布请求为目标，保持日期、金额、数量、对象和条件。
- 只使用任务明确给定的已知信息与已发生对话；未知信息不要猜测。
- 不因为 Agent 的建议自行新增偏好、任务或修改目标。
- 对明确要求的澄清正常作答。
- 继续遵循现有的场景限制和 grounded reply 机制，不再加一套新检查。

不把“中立”解释为“总是知道如何帮助 Agent 脱困”，也不把“更合作”写成这次新要求。

### 4.3 确认与权限

沿用现有场景约束中“只能批准符合原请求的操作”的语义。

此次不加入以下规则或背景：

- 助手已经获得所有账户权限。
- 用户必须在 Agent 拒绝后主动说“你有权限”。
- 默认批准所有操作、所有权限请求或所有后台命令。
- 用户必须提醒具体工具名、MCP、后台委派或执行方案。

用户会不会授权，继续由原任务范围、Agent 实际提问和现有权限交互决定。

### 4.4 信息披露与表达风格

移除通用模板中刻意制造客服式交互的要求：故意含糊开场、让 Agent 努力追问、机械地一次只说一项、假装忘记已知信息、尽早找主管。

中立替代只需表达：根据当前上下文自然回应，回答相关问题，必要时澄清。对任务明确要求逐步披露的内容仍遵守任务规则，不改变隐藏意图的发布机制。

用户仍可以表达不满、拒绝或困惑；这些应由任务和对话产生，而不是每道题统一注入投诉倾向。无需增加“永远耐心”或“禁止负面情绪”的规则。

### 4.5 结束与控制信号

新指南只保留当前 Gaia2 运行协议需要的 `###STOP###` 和 `###OUT-OF-SCOPE###` 说明，不再注入客服场景遗留的转人工信号。

保留“同意做不代表已经做完、当前请求尚有未完成事项时不能仅因一句承诺就结束”的语义。已有轮换、等待、停止判定、阶段推进继续工作；本次不引入新的停滞计数器或退出阈值。

关于沉默，使用中性状态询问措辞，保留既有等待/结束约定的意图，去掉必须表现愤怒的语气示例。具体物理等待阈值继续由现有配置控制。

对话结束和奖励成功依旧分别由当前机制记录。新角色没有权力宣布评测通过。

## 5. 人设内容采用显式组装，避免改动声学配置

### 5.1 为什么不能只把原 persona 整体清空

`RuntimePersona` 同时包含语言、声线、说话习惯和语用角色。把整个对象删除或换成一个默认对象，会改变声学选择、语言和打断行为，超出本次目标。

保留原对象供语音和语言机制使用，仅改变哪些文字进入 Gaia2 的角色提示。

### 5.2 具体选择

新的 Gaia2 指南不包含 `<PERSONA_GUIDELINES>` 占位符，避免 `build_user_system_prompt()` 自动注入 `RuntimePersona.to_guidelines_text()` 的完整结果。该占位符本来就只是可选文本替换，不需要改用户模拟器基类。

由新的小型 renderer 显式组合：

- 现有语言 directive；最终语言 reminder 继续由当前 `finalize_system_prompt()` 添加，避免重复。
- 原来的 verbosity 设置，可调用 `PersonaConfig.to_guidelines_text(persona, mode)` 获取基础部分，而不调用 RuntimePersona 的完整语用渲染。
- 中性的语法性别说明，由结构化 gender 字段构造；不复用带 customer 的 gender_guidance，不把语法性别扩展成新的社会身份。
- 语音模式下已有的拼写说明，保留“被明确要求拼写才逐字拼写”的规则。
- 当前 Gaia2 绑定里已有的 `user_guidelines`、`mode_guidelines` 任务边界与本地化说明，实施时核对其具体值，保留非人设约束。

不注入以下原始人设块：

- `gender_guidance` 中的客户身份措辞。
- `pragmatics_clauses` 的整套预设行为。
- `voice.pragmatics_clauses` 中投诉升级或截断对方等预设语用。
- 通用客户话术示例集合。

这意味着移除的是该角色包的预设语言行为，而不是只删几个英文单词。声线、发音、音效、语言配置、runtime interrupt_tendency 等控制参数继续使用原值；即使仍会打断，也应由已有语音机制决定。

不修改 `pack.yaml`、任务 JSON、数据库或已发布 benchmark pins，不创建新的语言包、人设注册系统或配置迁移。

## 6. 构造入口的具体接入

### 6.1 语音

在 `src/tau2/runner/build.py::build_voice_user()` 中，完成原来的声线和效果选择后：

1. 确认实际环境的 domain 为 `gaia2`。
2. 将生成的 Gaia2 中立指南放入现有 `domain_kwargs['global_guidelines_override']`。
3. 将中立提醒放入现有 `domain_kwargs['role_reminder_override']`。
4. 按现有路径构造 `VoiceStreamingUserSimulator`。

使用实际环境域来决定，不按模型名、镜像名、题号或是否启用 dynamic follow-up 决定。这样 Qwen 和其他待测 Agent 使用相同用户设定；Gaia2 的第一阶段与后续阶段也保持一致。

### 6.2 文本

在同文件的文本用户构造处，对 `UserSimulator` 的 Gaia2 实例设置 `global_guidelines_override`。

文本路径没有同一条语音 CUSTOMER 提醒，不为了统一接口额外新增 reminder 机制。两种模式只在说话/文本和语音说明上不同，采用相同的中立角色。

### 6.3 任务集合与其他领域

当前 `gaia2_hidden` 注册为任务集合，实际复用 Gaia2 环境。按实际环境 domain 接入，使相关任务使用同一中立身份，隐藏意图状态和披露逻辑仍走原路径。

airline、retail、telecom 和 intake 等领域继续通过各自现有构造逻辑生成提示。这里不是全局替换 customer 字样。

## 7. dynamic follow-up 和现有语音链路

dynamic follow-up 的源请求、生成触发、已发布事实、情绪继承、当前阶段提示继续使用原机制。此次不改成 ARE 的文字消息循环，不改变后续任务什么时候出现。

它可以继续根据真实对话生成“刚才没做成，接下来……”的自然措辞，但新的运行从开始就不再由默认客服人设驱动。无需在每次 follow-up 后增加“是不是在投诉”的检查或改写。

ASR、TTS、实际播放音频输入、空识别适配、轮换与后台执行均不参与本次角色修改。Agent 的提示、可见工具和委派实现也不在此次范围内。

## 8. 变更文件与预期规模

| 文件 | 变更 |
|---|---|
| `src/tau2/user/gaia2_guidelines.py` | 新增中立指南 renderer、角色提醒和简单版本标识 |
| `src/tau2/runner/build.py` | 语音、文本两个入口注入现有 override 参数 |
| 现有用户构造/场景语音测试文件，必要时新增一个小测试文件 | 开发阶段验证实际组装提示与模式隔离 |
| `docs/gaia2.md` | 简要记录新的用户角色与影响范围 |
| 本计划或实施记录 | 保存本次检查结果和实际差异 |

预期无需修改 `UserSimulator`、`VoiceStreamingUserSimulator`、`RuntimePersona` 的通用接口。若实施时发现仅用现有 override 不足，应优先找最小组装调整，不能据此扩展成用户模拟框架重构。

版本标识放在 Gaia2 专用提示的普通标题或已有可保存信息中，供历史结果区分；不增加新评分维度或每轮版本检查。涉及现有 runtime 指纹时，只沿用已有记录约定，不新增封存、全题回放或一致性验收流程，也不为本次改角色重新生成题目。

## 9. 实施顺序

1. 从当前实际组装的 Gaia2 用户提示提取必须保留的场景、语言和控制协议内容。
2. 编写独立中立指南和 reminder，显式选择保留的人设字段。
3. 在文本和语音构造入口注入 override，保持现有场景/模型选择路径。
4. 用 0760 的任务配置离线构造完整提示，人工查看新旧文本差异，确认残留角色来源已经切断。
5. 做第 10 节的少量离线检查，更新文档并交付。

实施不启动模型调用来“自查人设”，也不要求完整跑完三题后才算完成角色修改。

## 10. 轻量验收，仅发生在开发阶段

### 10.1 两组针对性检查足够

**A. Gaia2 实际组装路径。** 用现有 builder fixture 覆盖 text/voice；语音采用 0760 对应的原人设配置。检查中立身份已生效、每轮 reminder 是中立版本、默认客户/主管语用块没有被注入，同时任务事实、当前语言和必要控制信号保留。只对受控 fixture 做文本断言，不把这些断言写到生产运行中。

**B. 配置隔离。** 检查构造前后的原 persona 与 voice 配置未被修改，另用一个非 Gaia2 fixture 确认仍走原有指南。复用既有测试，不对每个内部函数分别写重复测试。

对修改文件运行必要的语法/格式/lint 检查即可。不增加大范围评分回归，不重新评分历史结果，不增加 live API smoke 或完整题目重测作为前置条件。

### 10.2 明确不增加的运行负担

- 没有逐轮人设审查或客服关键词检测。
- 没有用户回复后的自动修订或重生成步骤。
- 没有新的权限裁判、任务完成裁判或情绪裁判。
- 没有每题前置验收、提示审计或业务状态检查。
- 没有为了保持中立而添加硬拦截或取消评分的条件。
- 没有增加模型调用次数。

已有模拟和评分机制继续使用；本次保证范围的是构造时选对提示，而不是运行中不断验证角色。

## 11. 完成标准与预期

完成后，Gaia2 用户的实际模型输入应表达为：一个持有当前任务、依据已知信息与实际对话回应的普通委托者。默认客户、客服和找主管人设不再通过共享模板或 persona 注入。

任务知识边界、隐藏意图、阶段发布和语音控制继续由现有机制管理。用户是否主动确认、等待、澄清或不满，取决于任务和对话，不预设其必须配合成功。

结果中仍可能出现 Agent 错误拒绝、无法委派或 ASR 识别问题。这些不能通过本次角色修改保证消失。后续若重测，只需按新的用户设定明确记录运行版本，不把分数提高作为修改正确性的验收要求。
