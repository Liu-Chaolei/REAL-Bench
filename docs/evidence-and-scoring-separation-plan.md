# 请求来源、公共媒体证据与评分顺序修复计划

状态：已实施。来源诊断传递、公共媒体读取、摘要评分与先保存后评分已落地。

## 1. 目标

本轮解决三个已确认的问题：

1. 运行轨迹已有请求来源，但诊断转换没有完整保留；交互变体迁移输出位置后，部分诊断读取端仍访问旧位置。
2. 精简性音频统计从语音评分结果中读取 `waveform_evidence`，而新语音评分分支不再返回该字段。
3. 部分后台和变体评分发生在原始轨迹保存之前；变体 evaluator 仍依赖活的 Controller。

修复围绕三个接口进行：

- 请求来源和机制摘要的统一读取。
- 公共媒体事实的统一读取。
- 基于已保存摘要的独立评分。

依靠数据流和执行顺序保证正确性，不新增通用调度框架、运行时审计或自动修复系统。

## 2. 目标执行流程

```text
运行对话并收集事实
        ↓
生成运行摘要，保存原始轨迹
        ↓
保存诊断证据和媒体证据
        ↓
各评分器读取已保存事实
        ↓
保存评分结果或评分错误
```

原始证据不以某项评分成功为前提；单项评分失败不能使已完成的交互丢失，也不能变成 Agent 能力零分。

## 3. 统一请求来源并接通诊断读取

### 3.1 诊断输入保留来源

在 `src/tau2/data_model/diagnostics.py` 的 `UserInput` 中增加可选字段：

```python
source: str | None = None
purpose: str | None = None
```

新记录沿用当前来源值：

```text
scenario
scenario_stage
interaction_variant
active_persistent_task
```

用途沿用：

```text
scripted_request
stage_request
temporary
followup
```

`source` 表示请求由哪个机制产生；`purpose` 表示该请求的用途。两者不合并。

### 3.2 从实际交付记录传递

调整 `diagnostics/collect.py` 中的 `delivered_inputs()`：

1. 从实际交付的消息或语音组取得 `event_id`。
2. 按 `event_id` 对应 `environment_trace` 中的来源和用途。
3. 将来源写入诊断 `UserInput`，保持原有文本、时间、阶段和完整交付信息。
4. 同一请求中断后再次交付时，各条交付继续保留，不按请求 ID 合并。
5. 不具有可靠来源的历史记录保持 `None`，不根据文本猜测。

来源的定义仍由运行时负责；诊断层只传递事实，不另建一套来源分类策略。

不要为了获取来源改写请求文本、重新排队、改变 Stage 推进或音频播放时机。

### 3.3 诊断证据保留两个当前摘要入口

`finalize_evidence()` 保存当前运行摘要：

```text
active_metrics.metrics.persistent_task
scenario_mechanisms.mechanisms.interaction_variant
```

摘要包括：

- 请求和 phase。
- 实际交付时间及状态。
- 后台任务绑定。
- 原生操作和结果。
- 已交付回复。
- 运行状态及必要版本信息。

原始证据中只保存运行事实，不复制 `scores`。

### 3.4 统一变体和 active 摘要读取

在 `diagnostics/request_changes.py` 中增加一个小型公共读取函数，统一取得运行摘要，再供以下函数使用：

- `management_events()`。
- `request_relations()`。
- `feedback_evidence()`。

当前三个函数均直接读取旧 active 位置。修改后应能读取新变体位置，同时保持 active 摘要读取。

历史回退限定为：

- 新位置存在时优先使用。
- 新位置不存在，且旧 active 摘要含有明确的 `variant_type` 时，才按历史变体读取。
- 同一变体不同时读取新旧两份摘要，避免重复统计。

按 `call_id` 连接操作开始和返回记录；按稳定 request ID 连接请求关系。缺少对应事实时保留缺失，不推测后台操作或目标绑定。

### 3.5 来源继续进入诊断消费者

向 intent 等诊断输入继续传递 `source/purpose`，保留请求关系及授权历史。

本轮只修复信息传递，不根据来源重新定义需求覆盖、语音响应分母或指标公式。

## 4. 公共媒体证据接口

### 4.1 抽取媒体事实读取函数

建议在公共诊断媒体模块提供：

```python
read_media_activity(evidence, directory)
```

返回计算所需的最小事实：

- 状态和缺失原因。
- 媒体时间基准。
- Agent 实际语音区间。
- 用户语音和分类信息（有证据时提供）。
- 实际播放时间线。
- 媒体总时长。

接口不返回响应率、打断率或精简性得分。

### 4.2 新旧媒体路径

新证据：

- 直接读取 `evidence.audio.activity`。
- 复用已保存媒体时间线。
- 已有语音活动区间时不重新执行检测。

历史音频证据：

- 将当前 `evaluate_voice()` 内的文件读取、格式转换和语音区间提取移入公共读取函数。
- 保持现有检测方法与参数。
- 按需处理当前证据，不扫描历史结果目录。

本轮不增加媒体预处理服务、后台缓存系统或额外模型调用。

### 4.3 两类评分读取相同证据

调整后：

```text
公共媒体事实
    ├── voice_interaction 评分
    ├── 历史 real_voice 评分适配
    └── conciseness 音频统计
```

- `diagnostics/voice.py` 从公共证据计算语音指标。
- `conciseness._audio_stats()` 直接计算说话时长和播放时长。
- 精简性模块不再调用 `evaluate_voice()`。
- 区间计算使用公共区间工具，不依赖另一个评分模块的私有函数。
- 不通过给语音评分结果补回 `waveform_evidence` 来维持长期依赖。

### 4.4 时间和缺失状态

所有公共区间明确使用媒体相对秒；历史绝对时间转换复用现有媒体时间映射函数。

注意：

- 避免重复扣除媒体时间原点。
- 语音区间缺失与真实没有语音不同。
- 只有证据可靠且区间为空，才可计算为零。
- 证据缺失时返回不可用及原因。
- 缺少用户事件分类不能使可用的 Agent 时长统计一起失效。

不增加运行时一致性巡检，以上规则由接口输入、分支和返回状态实现。

## 5. 根据已保存摘要评分

### 5.1 提供独立函数

建议抽出：

```python
score_persistent_task(summary, scoring)
score_interaction_variant(summary, scoring)
```

公共后台评分负责：

- 交付后的操作归属。
- 原生操作实际结果。
- 已交付回复与结果的一致性。

变体评分负责：

- modify／cancel／addtask 的评分适用范围。
- primary／temporary 等角色绑定。
- 目标状态。
- 调用公共后台评分逻辑。

### 5.2 不依赖运行对象

评分输入仅使用已保存摘要中的：

- operations。
- delivery。
- binding／bindings。
- reply_text。
- resolved intent。
- variant type 和 binding status。
- 运行状态及必要评分参数。

不访问 Agent、Provider、Runtime 或 Controller；不执行工具、不推进状态、不追加用户请求。

先复用现有摘要字段，只补缺失的必需信息，不设计新的大型证据模型。

### 5.3 Controller 与旧评分方法

Controller 和 active runtime 继续负责运行、事实记录和摘要生成。

当前 `InteractionVariantEvaluator` 转调 `controller._score()` 的路径需要替换。新 evaluator 接受摘要，不重建 Controller。

若保留现有 `score()` 供调用方过渡使用，它只能包装独立评分函数，不再持有单独一份评分实现。

### 5.4 保持评分含义

第一轮保持：

- 现有完成分公式。
- 操作成功和回复判断规则。
- `not_applicable`、`unsupported`、目标未绑定等状态含义。
- active 和变体分数不自动乘入主任务 reward。

接口修复不混入指标口径调整。线上与离线使用同一个评分实现。

## 6. Runner 先保存再评分

### 6.1 执行顺序

调整 `runner/simulation.py`：

1. 执行 `orchestrator.run()`。
2. 获取完整对话、环境轨迹、active 摘要和变体摘要。
3. 补齐 trial、语言及运行元信息。
4. 将评分状态设置为现有的 `pending`。
5. 调用 `on_trajectory_ready()` 保存原始轨迹。
6. 完成诊断证据和媒体证据落盘。
7. 分别执行主任务 reward、active、交互变体和 diagnostics 评分。
8. 返回带评分或评分错误的 `SimulationRun`。
9. 由现有 batch／checkpoint 路径保存最终结果。

运行摘要应在评分前确定；评分不得再次 drain Provider 事件或改变摘要。

### 6.2 原始轨迹与最终结果

原始轨迹快照：

- 包含完整对话及各机制的事实摘要。
- 不以评分成功为前提。
- 不被后续评分结果覆盖。

最终结果：

- 使用现有结果保存和 checkpoint 路径。
- 包含评分状态、分数、错误和诊断引用。
- 与原始轨迹通过同一个 simulation ID 对应。

证据目录沿用现有确定路径。不新增恢复数据库、写前日志或多份备份机制。

### 6.3 各类失败边界

原始轨迹保存失败：

- 向调用方报告保存失败。
- 不假装已保存后继续执行评分。

诊断证据收集失败：

- 保留已保存轨迹。
- 记录现有 `collection_error`。
- 依赖缺失证据的指标不可用。
- 主任务仍具备完整所需事实时，可继续评分。

单项评分失败：

- 在该项结果中记录 `grader_error` 和异常类型。
- 继续其他独立评分。
- 不改成 Agent 运行失败。
- 不清空轨迹，不填零。
- 原始证据保持可供后续读取。

运行本身异常：

- 保留现有运行异常语义。
- 本轮不扩展成任意进程崩溃情况下的完整恢复系统。

低层直接调用没有提供保存回调或目录时：

- 保证先形成内存事实，再评分。
- 不声称结果已持久化。

## 7. 原始证据与结果边界

### 7.1 原始诊断证据不依赖已有分数

当前 suite 的 persistent-task 分支读取：

```text
evidence.source.active_metrics.scores.persistent_task
```

需要改为：

- 读取 active 运行摘要。
- 调用独立评分函数。
- 将结果保存到现有 evaluation 输出。

这样离线诊断不要求线上评分已经成功，也不会把评分输出当作原始事实。

### 7.2 结果沿用现有位置

本轮不再次迁移所有评分输出：

| 内容 | 保存位置 |
| --- | --- |
| 主任务评分 | `reward_info` |
| active 评分 | `active_metrics.scores` |
| 变体评分 | `scenario_mechanisms.scores` |
| diagnostics | 现有 evaluations 目录及结果引用 |

原始证据只保留事实摘要，评分写在结果区域，不回填原始证据文件。

### 7.3 版本与历史读取

- 为发生变化的证据契约和评分实现记录必要版本。
- 可选来源字段允许缺失，历史缺失来源不猜测。
- 历史保存分数仍可展示。
- 历史变体旧位置由单一读取函数有限回退。
- 不覆盖历史证据和冻结数据。
- 受修复影响的诊断缓存随实现版本更新而失效。
- 不因此全量重算主任务 reward。

沿用现有版本和缓存机制，不增加独立迁移框架。

## 8. 实施顺序

1. 增加诊断 `source/purpose`，接通实际交付来源。
2. 保存新变体摘要，统一 `request_changes` 读取。
3. 抽取公共媒体证据读取函数。
4. 接通语音评分和精简性音频统计。
5. 抽取基于摘要的后台与变体 evaluator。
6. 修改 suite，不再要求原始证据含有 scores。
7. 把 Runner 所有评分移到原始轨迹保存之后。
8. 更新版本、文档和少量历史读取兼容。
9. 执行小范围测试和改动文件静态检查。

本轮不调整参考事件触发、Stage 推进规则或诊断快照临界区。

## 9. 轻量验证范围

优先扩展已有测试，使用内存事件、小型音频样例和假评分器：

1. Stage、普通脚本、active、变体来源正确进入诊断输入。
2. 部分交付与重试记录不会因来源连接被合并。
3. 新变体位置能被三个诊断读取函数消费；历史回退不重复计数。
4. 新音频区间可以直接计算精简性时长，不调用语音评分器。
5. 历史波形路径保持预期时长；缺失和真实零语音区分。
6. JSON 保存并重载的摘要能够独立评分，不依赖运行对象。
7. 假评分器抛异常前，原始轨迹已经保存；其他评分仍可完成。
8. 保存回调失败时，不启动评分。

完成后运行改动文件 Ruff 和对应小范围测试。

不要求真实 API、全量 1000 题、全量历史回放或额外 LLM 验收。不把上述测试搬进正式评测运行流程。

## 10. 机制边界

正式评测只执行任务本身需要的采集、保存和评分：

- 请求 ID 连接来源及关系。
- 公共媒体读取函数提供时长事实。
- 摘要评分函数读取固定输入。
- 保存回调先于评分。
- 每项评分分别记录错误。

不新增：

- 全量数据扫描。
- 运行时自动修复。
- 多层验收状态。
- 全量 replay 比对。
- 自动重跑对话以修复评分失败。
- 额外裁判模型或后台巡检。

## 11. 完成标准

- 新轨迹中的请求来源和用途能进入诊断输入。
- 变体管理操作、请求关系和反馈窗口不再因输出位置迁移而漏读。
- 精简性音频统计直接读取公共媒体事实。
- 新语音证据不再因缺少 waveform_evidence 评分输出而导致音频统计不可用。
- active 和变体均能对保存后重载的摘要独立评分。
- 所有评分发生在原始轨迹保存之后。
- 原始证据文件不包含评分输出依赖。
- 单项评分失败不会改变已完成的运行事实或阻断其他独立评分。
- 未引入正式评测中的重型验收和自动修复机制。

## 12. 实施记录

- 新诊断证据版本为 `tau-diagnostic-evidence/2`，历史证据仍可读取。
- `diagnostics/media.py` 提供公共媒体事实读取，使用相对媒体秒。
- 后台与变体独立评分分别位于 active persistent-task 的 `evaluator.py` 和
  `variant_evaluator.py`；运行对象的 `score()` 仅作兼容包装。
- `on_trajectory_ready()` 在诊断证据落盘及所有评分之前执行；无回调不保证落盘。
- 原始诊断包剔除 scores；离线 suite 从摘要评分，自动诊断复用本次计算结果，
  不重复调用已有后台回复裁判。
- 验证使用本地事件、短音频和假评分器，未新增运行时验收、自动修复或全量回放。

验证结果：220 项相关本地测试通过（约 10 秒），包括来源传递、变体新旧位置、
新旧媒体路径、JSON 摘要评分、保存失败及各类评分失败隔离。
改动文件 Ruff、格式检查和差异空白检查通过。未调用真实模型，未执行全量题集。
