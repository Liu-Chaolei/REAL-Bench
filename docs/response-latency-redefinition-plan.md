# 语音响应延迟重新定义与实施计划

状态：已实施。统一语音指标已使用 `tau-voice-interaction/4`，历史记录保留旧口径。

本计划调整统一语音指标中的响应判定。前置的统一音频检测、实际播放时间线和用户正式发言分类已经完成，见 [统一发声判定与音频时间记录计划](unified-speech-timing-plan.md) 和 [语音交互指标合并计划](voice-interaction-metrics-unification-plan.md)。

## 1. 修改目标

当前规则把“用户发言结束时 Agent 仍在说话”直接记为 0 秒响应。这个结果无法区分两种情况：

- Agent 已经停止并在用户结束后开始回答；
- Agent 一直占着话筒，没有让话。

新的规则要求：

> 只有在用户正式发言结束后，新开始的一段 Agent 发言，才算对这次发言作出响应。

用户结束时仍在继续的 Agent 发言，不再自动算作 0 秒响应。它只进入让话、主动打断和重叠统计。

本次只调整响应事件的定义，不改变用户正式发言分类、200 毫秒发言分组、1 秒停声确认、两种 Agent 打断率、重叠时长或题目等权汇总原则。

## 2. 新的响应规则

每次正式用户发言建立一条响应记录：

```text
formal_turn_id
user_start
user_end
observation_end
responded
response_start
response_latency
response_group_id
```

响应观察范围从用户发言结束开始，直到：

- 下一次正式用户发言开始；或
- 通话结束。

附和、咳嗽、口头语、非定向讲话、背景声、静音和内部结束信号不截断这个范围。

### 2.1 响应成立条件

只寻找 Agent 发言分组中满足以下条件的第一段：

```text
agent_group.start >= user_end
agent_group.start < observation_end
```

找到后：

```text
responded = true
response_start = agent_group.start
response_latency = agent_group.start - user_end
response_group_id = agent_group.id
```

找不到时：

```text
responded = false
response_start = null
response_latency = null
```

未响应正式发言仍然进入 `response_rate` 的分母，但不制造一个虚构的延迟值。

### 2.2 边界情况

| 情况 | 响应结果 |
| --- | --- |
| 用户结束时 Agent 安静，之后新开口 | 正常计算延迟 |
| 用户结束时 Agent 仍在持续说话 | 不算响应 |
| Agent 在用户发言过程中开始说，并持续到用户结束 | 不算响应，属于 Agent 打断或重叠 |
| Agent 在用户发言过程中停止，用户结束后重新开口 | 重新开口的分组算响应 |
| Agent 发言分组刚好在用户结束时开始 | 响应延迟为 0 |
| 用户结束后直到观察范围结束都没有新发言 | 未响应 |
| Agent 在用户发言前开始，用户结束后仍属于同一发言分组 | 不算响应 |

“Agent 仍在说话”只是一个状态信息，不再直接转换成 0 秒响应。

## 3. Agent 发言分组

继续使用统一语音指标已经确定的 200 毫秒规则：

- 相邻有声区间之间的静音间隔小于 200 毫秒，归为同一段 Agent 发言。
- 静音间隔达到或超过 200 毫秒，形成新的 Agent 发言分组。
- 原始声音区间始终保留，分组不会把静音填成有声。

例子：

```text
有声 [0.0, 1.0]
静音 [1.0, 1.1]
有声 [1.1, 2.0]
```

两段声音属于同一分组。如果用户在 1.05 秒结束，1.1 秒的声音不是新响应起点。

```text
有声 [0.0, 1.0]
静音 [1.0, 1.25]
有声 [1.25, 2.0]
```

两段声音属于不同分组。如果用户在 1.1 秒结束，1.25 秒可以作为响应起点，延迟为 0.15 秒。

分组结果应作为统一中间证据保存：

```text
agent_group_id
start
end
source_intervals
```

响应、Agent 主动打断和 selectivity 都读取这份分组结果，避免每个指标使用不同的开口判定。

## 4. 四项响应指标的计算

### `response_rate`

```text
已响应正式发言数 / 正式发言总数
```

每次正式发言最多贡献一个响应分子。Agent 连续说多段，也不会让同一次正式发言重复计入。

### `response_latency_mean`

```text
所有已响应正式发言的 response_latency 平均值
```

只有用户结束后的新 Agent 发言分组才生成延迟样本。未响应正式发言不进入平均值。

### `response_latency_p90`

使用与 `response_latency_mean` 完全相同的延迟样本，并保留已确认的题目等权加权分位数：

1. 每道有适用响应样本的题目获得相同总权重。
2. 同题多次试验平分该题权重。
3. 每次试验的响应样本平分该试验权重。
4. 按延迟从小到大排序，累计权重首次达到 0.9 时取对应延迟。

0 秒响应属于有效样本。未响应不填入无穷大或人为的大延迟。

### `on_time_rate`

```text
已响应且延迟小于及时上限的记录 / 已响应记录
```

继续采用：

- 无工具时延迟小于 2.75 秒；
- 有工具时延迟小于 4 秒；
- 不设置 0.2 秒下限；
- 0 秒响应算及时。

## 5. 与让话、打断和重叠的关系

### 5.1 让话

用户正式发言开始时，如果 Agent 已经处于发言分组中，则形成让话观察：

- Agent 是否停止，由连续 1 秒静音确认；
- `yield_latency_mean` 记用户开始插话到实际停声的时间；
- `yield_rate` 记录是否观察到确认停声；
- 没有 2 秒或其他及时期限。

Agent 持续说到用户结束时：

- 不算响应；
- 仍然可以形成让话失败或观察不足；
- 仍然计入重叠时长。

### 5.2 Agent 主动打断

如果 Agent 发言分组在用户正式发言已经开始、但还没有结束时开始，生成 Agent 主动打断事件。

如果 Agent 在用户开始之前就已说话，用户随后插话，不生成 Agent 主动打断事件。此时主要由让话和重叠指标描述。

保留两项指标：

```text
agent_interruption_event_rate
    = Agent 主动打断事件数 / 正式发言数

agent_interrupted_turn_rate
    = 至少被主动打断一次的正式发言数 / 正式发言数
```

### 5.3 重叠时长

`speech_overlap_duration` 继续使用原始用户和 Agent 有声区间的交集，不使用分组后的合并区间。

因此，分组中的短暂停顿不会被算成重叠声音。

## 6. 推荐的统一事件提取流程

```text
用户实际发言区间
        ↓
正式发言列表
        ↓
Agent 原始有声区间
        ↓
200 ms Agent 发言分组
        ↓
响应记录 ──────→ response_rate / latency_mean / p90 / on_time_rate
        ├────────→ 让话记录
        ├────────→ Agent 主动打断记录
        └────────→ 原始区间重叠记录
```

不让各个指标重新从 `contains_speech` 或 TICK 布尔值推断响应。

## 9. 轻量验证

只增加少量人工时间区间测试，验证机制：

1. Agent 在用户开始前开口，并持续到用户结束：不算响应。
2. Agent 在用户结束后新开口：正确计算延迟。
3. Agent 分组刚好在用户结束时开始：延迟为 0。
4. Agent 在用户发言中打断并持续到结束：计打断和重叠，不计响应。
5. Agent 在用户发言中停止，用户结束后重新开口：重新开口计响应。
6. Agent 停顿 100 毫秒后继续：不产生新的响应起点。
7. Agent 停顿 250 毫秒后继续：可以产生新的响应起点。
8. 未响应正式发言进入响应率分母，但不进入平均延迟和 P90。
9. 持续发声触发让话观察，但不改变响应结果。
10. 同题多次测试和多题汇总仍保持题目等权。

不调用真实模型，不重跑完整数据集，不增加运行时双版本评分、每轮断言、评分后审计或自动重试。统一分组和统一响应记录机制负责保证各指标使用同一事实。

## 10. 实施记录

统一计算已切换到 `tau-voice-interaction/4`：响应只来自用户结束后的新 Agent 发言分组，持续旧发言进入让话、打断和重叠记录。29 项针对性边界测试及合并后的 294 项相关离线测试通过；Ruff 和 `git diff --check` 通过。未调用模型 API，也未增加评测运行时检查。

## 11. 完成后的预期结果

响应指标只反映真正的新回应起点：

- Agent 一直说话而没有让话，不再产生虚假的 0 秒响应；
- Agent 打断用户的声音，不再被当作对该次用户发言的响应；
- Agent 在用户结束后重新开始说话，才产生响应延迟；
- 让话、打断和重叠继续保留各自的含义；
- 未响应由响应率记录，延迟指标只处理真实响应样本。
