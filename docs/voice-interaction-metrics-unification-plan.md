# 语音交互指标合并实施计划

状态：已实施。新分类媒体记录使用 `tau-voice-interaction/4`，统一输出 12 项语音指标；历史记录保留原有口径。

前置工作见 [统一发声判定与音频时间记录计划](unified-speech-timing-plan.md)。公共声音检测和媒体时间记录已经完成；本次在这些证据之上统一语音指标，不重新改造检测方式。

## 1. 目标与范围

把原 τ-voice 路径和媒体路径合并为一套语音指标计算流程。统一正式发言、响应关联、发言分组、让话、主动打断和汇总口径。

用户侧使用模拟器已知的实际发言范围，Agent 侧使用公共音频层产生的原始有声区间与实际播放时间。

本次保留 12 项主要语音指标，以及现有通话级 selectivity 派生标记。任务结果、需求理解、执行质量和其他沟通质量指标不属于本次修改范围。

实现以共同事件记录为基础：先记录每次发言之后发生了什么，再计算各项指标。通过单一信息来源与明确的数据归属保证一致性，不在评测系统里添加验收、双版本对照或重复评分机制。

## 2. 已确认的规则

| 内容 | 统一后的规则 |
| --- | --- |
| 正式发言 | 模拟器正常产生的发言默认属于正式发言；排除专门生成的附和、独立插入的咳嗽／口头语／非定向讲话、背景声、静音和内部结束信号 |
| 响应关联 | 按时间关联，每次正式发言建立一条响应记录 |
| 用户结束时 Agent 正在发声 | 这段旧发言不算响应；只有用户结束后新开始的 Agent 发言分组才算响应 |
| 用户结束时 Agent 没有发声 | 等待随后第一次实际发声，计算响应延迟 |
| 响应观察范围 | 到下一次正式发言开始或通话结束；独立附和、咳嗽等不截断范围 |
| 响应率 | 获得响应的正式发言数／正式发言数 |
| 平均延迟和 P90 | 共用用户结束后新发言分组产生的已响应样本；分组恰好在用户结束时开始时延迟为 0 |
| Agent 发言分组 | 间隔不足 200 毫秒的声音归为一次发言 |
| 让话确认 | 连续静音至少 1 秒 |
| 让话及时期限 | 不设置；去掉原来的 2 秒停声期限 |
| 让话延迟 | 从用户正式插话开始到实际停声点，不包含 1 秒确认等待 |
| 末尾不足 1 秒的静音 | 记录观察不足，不直接算让话成功或失败 |
| Agent 打断指标 | 保留打断事件率与被打断轮次率，分母统一为正式发言数 |
| 重叠时长 | 使用原始声音区间，按正式发言计算平均重叠秒数，包括零重叠 |
| On Time Rate | 取消 0.2 秒下限；无工具上限 2.75 秒，有工具上限 4 秒；分母保留已响应样本 |
| 三项 selectivity | 共用连续静音 1 秒的停声确认，保留原有事件类型和观察范围 |
| 普通汇总 | 同题试验先平均，再对题等权平均 |
| P90 汇总 | 题目等权的加权分位数；用户已明确同意，不再是待确认项 |

## 3. 正式发言与用户事件分类

### 3.1 在生成位置标记用途

按内容的生成来源分类，不根据事后转写猜测，也不增加模型裁判：

| 用户侧内容 | 用途 |
| --- | --- |
| 正常请求、补充说明、追问、修改要求、正式插话 | 正式发言，需要回应 |
| 单独专门生成的“嗯”“对”等 | 附和 |
| 独立插入的咳嗽、口头语 | 口头语／非语言事件 |
| 独立插入、不是对 Agent 说的话 | 非定向讲话 |
| 背景声、静音 | 环境音频 |
| 内部停止、转交等控制内容 | 框架控制事件 |

正式发言内部存在停顿、口头语或混合背景声，不改变整次发言的正式属性。排除的是独立生成或独立插入的事件。

### 3.2 以一次实际发言为单位

- 同一次发言拆成多个音频包，继续使用同一个发言 ID。
- 保存生成用途、实际送入开始和结束位置。
- 尚未发送的预生成内容不进入分母。
- 独立音效在正式发言期间出现时，保留它自己的事件类别，不取消主发言的正式属性。
- 复用既有发言、附和和音效元数据，缺少字段时在源头补齐，不建设通用事件平台。

## 4. 三层时间信息

| 信息 | 主要用途 |
| --- | --- |
| 用户正式发言的实际起止 | 正式发言分母、响应关联、用户插话 |
| Agent 原始有声区间 | 是否正在发声、首次响应、停声确认、实际重叠 |
| Agent 发言分组 | 一次新开口、Agent 主动打断计数 |

### 4.1 200 毫秒分组

相邻 Agent 有声区间之间静音不足 200 毫秒，归为同一次发言；静音达到 200 毫秒，分为两次发言。

分组只建立归属关系，不能修改原始有声区间。合并进去的静音不会变成有声。

例如“有声—静音 100 毫秒—有声”属于同一次发言；用户在这段静音中结束时，仍不能把同一分组当作新响应。只有静音达到 200 毫秒，恢复的声音才可能成为新的响应起点。

### 4.2 声音边界约定

时间区间采用开始包含、结束不包含的表示。只有新的 Agent 发言分组恰好在用户结束时开始，才记为 0 秒响应；已经在用户结束前开始的分组，即使延续到用户结束之后，也不算响应。

Agent 与用户同时开始发言不直接认定为 Agent 主动打断；主动打断要求用户发言已经开始且尚未结束。

这些是实现所需的确定性边界约定，不增加额外评分或运行检查。

## 5. 一条响应记录计算四项指标

### 5.1 响应记录

每次正式发言产生一条记录，至少包含：

```text
用户发言 ID
用户开始、结束时间
观察结束时间
是否已响应
响应开始时间
响应延迟
对应观察范围内的工具上下文
```

观察结束时间是下一次正式发言开始或通话结束。独立附和、咳嗽等不自动关闭前一次请求的观察范围。

### 5.2 关联顺序

1. 用户结束时 Agent 原始声音区间仍处于有声状态：已响应，延迟为 0。
2. 否则，寻找观察范围内第一次 Agent 实际发声：已响应，延迟为发声时间减用户结束时间。
3. 没有找到：未响应。

每次正式发言最多贡献一个已响应计数。Agent 回答了多段，也只算一次。

不限制一段持续 Agent 发言只能关联一次用户发言。用户提出新的正式要求并结束时，Agent 仍在发声，就按本轮确认的规则记为已响应、延迟为 0。

没有待回应正式发言时，对附和或噪声开口、Agent 主动讲话等不增加响应率分子。存在待回应正式发言时，依照已接受的时间关联规则归属，不新增语义因果判别。

响应指标评价时间上的回应；是否理解新要求、回答是否正确和有用，继续由其他指标体现。

### 5.3 四项输出

| 指标 | 公式 |
| --- | --- |
| `response_rate` | 已响应正式发言数／正式发言数 |
| `response_latency_mean` | 用户结束后新 Agent 发言分组产生的已响应样本延迟平均值；持续旧发言不产生 0 秒样本 |
| `response_latency_p90` | 同一批延迟的第 90 百分位 |
| `on_time_rate` | 已响应样本中，延迟小于及时上限的比例 |

未响应不转换成一个虚构的大延迟，不塞入平均延迟或 P90；通过响应率体现。

### 5.4 On Time Rate

- 取消延迟至少 0.2 秒的要求。
- 无工具时，延迟小于 2.75 秒算及时。
- 有工具时，延迟小于 4 秒算及时。
- 0 秒响应算及时。
- 工具关联沿用现有调用记录和观察范围，不在本轮增加“任务理论上是否需要工具”的判别。
- 保留未回应、工具上下文缺失等明细的现有日志表达，不补造数值。

## 6. 统一的 1 秒停声确认

### 6.1 停声机制

1. 从有声转为静音，保存候选停声时间。
2. 不到 1 秒又有声音，撤销候选。
3. 连续静音达到 1 秒，确认停止。
4. 实际停声时间仍取候选起点，不加确认等待。

确认逻辑使用原始声音时间线。普通发言分组的 200 毫秒规则不能代替 1 秒确认。例如静音 300 毫秒后恢复发声，可以形成新发言分组，但不满足让话条件。

这套机制从已记录的区间计算即可，不需要评分代码真正等待一秒。

### 6.2 正式让话记录

用户正式插话开始时，Agent 正处于一次发言中，形成一次让话观察。若用户开口恰逢该发言内部的短暂停顿，候选停声时间从用户开口时起算，避免负延迟；仍要求此后完整观察到连续 1 秒静音。

在通话剩余可观察时间内寻找符合条件的停止：

- 找到：让话成功，记录实际停声延迟。
- 没找到，且末尾没有不足一秒的待确认静音：记录未观察到让话。
- 末尾存在不足一秒的待确认静音：记录观察不足。

没有 2 秒或其他“必须及时停声”的期限。一次停声可以结束多个先后发生的插话观察，每个插话按自己的开始时间计算延迟，不凭空制造额外停止事件。

### 6.3 指标

```text
yield_rate
    = 成功让话次数 / 可以明确判断结果的正式插话次数

yield_latency_mean
    = 成功让话样本的平均停声延迟
```

观察不足数量及原因放入评测日志，不直接记为成功或失败。没有适用正式插话时，指标为空。

## 7. Agent 主动打断与重叠

### 7.1 主动打断事件

一次新的 Agent 发言分组开始时，用户正式发言已经开始且尚未结束，生成一次 Agent 主动打断事件。

如果 Agent 原本就在说话，随后用户插话，不生成 Agent 主动打断事件。短暂停顿不足 200 毫秒后恢复声音，仍属于原发言，不重复计新开口。

每个事件保留用户发言 ID、Agent 发言分组 ID 和开始时间。

### 7.2 两种打断指标

| 输出字段 | 定义 |
| --- | --- |
| `agent_interruption_event_rate` | 主动打断事件数／正式发言数，可以大于 1 |
| `agent_interrupted_turn_rate` | 至少被主动打断一次的正式发言数／正式发言数，范围为 0～1 |

同一轮被打断多次，前者计多次，后者只计一次。两项共用分母和事件集合，不再使用原 τ-voice 的响应事件分母。

### 7.3 重叠时长

计算每次正式发言的实际送入区间与 Agent 原始有声区间的交集长度。

`speech_overlap_duration` 输出每次正式发言的平均重叠秒数，包括零重叠的正式发言。

用户插话产生的重叠也计入，不要求必须先有 Agent 主动打断事件。分组时合并的静音不计入声音时长。累计重叠秒数留在明细中，不额外增加一个主指标。

## 8. 三项 selectivity 与通话标记

保留：

- `selectivity_backchannel`：对用户附和的正确处理率。
- `selectivity_vocal_tic`：对咳嗽、口头语等独立事件的正确处理率。
- `selectivity_non_directed`：对非定向讲话的正确处理率。

三项共用事件处理机制，但分别统计。

当 Agent 原本正在发言时，判断对应观察范围内是否出现经 1 秒静音确认的停止。候选停声点需要落在原有观察范围内；确认所需的一秒可以延续到范围之后。若通话结束使确认不足，记录观察不足。

当 Agent 原本安静时，口头语或非定向讲话是否触发错误开口，沿用现有的响应观察规则和时长。

本轮保留这些事件原有的观察范围，不把正式让话取消及时期限的决定扩展到 selectivity，也不引入因果或语义裁判。

通话级 `selectivity` 标记继续使用“三类错误合计超过 3 次”的规则，直接从统一记录派生，不再独立提取或计算另一套事件。

## 9. 题目等权汇总与 P90

### 9.1 普通指标

1. 每次试验先计算自己的均值或比例。
2. 同一道题多次适用试验先平均。
3. 再对有适用值的题目等权平均。

没有适用事件的指标保留为空，不代入 0 或 1。有效题目数、试验数和事件数留在日志。

沿用已有题目身份规则，包括领域、语言、任务集和题目 ID，不把不同任务误合为同题。

### 9.2 P90：已确认采用题目等权的加权分位数

汇总 P90 不把所有响应样本无权重拼在一起，也不简单平均各题 P90。

具体权重：

1. 对当前有响应延迟样本的每道题，分配相同的总权重。
2. 题内对有延迟样本的各次试验等分权重。
3. 一次试验内，对每个响应延迟样本等分该试验的权重。

若有 N 道适用题，第 i 题有 Rᵢ 次适用试验，第 j 次试验有 Mᵢⱼ 个响应样本，则每个样本权重为：

```text
wᵢⱼₖ = 1 / (N × Rᵢ × Mᵢⱼ)
```

按延迟从小到大排序并累计权重，取累计权重第一次达到 0.9 时的延迟，作为统一 P90。该分位数约定采用加权经验分布的逆函数，方便明确解释和复算。

0 秒响应照常参与。没有响应样本的试验和题目不能构造延迟，记录其数量，并由响应率体现未响应情况。

单次试验 P90 也使用相同分位数约定，样本等权。实现时明确记录新指标版本，不与历史线性插值 P90 混称同一口径。

## 10. 输出结构与日志

建议统一能力输出分组为 `voice_interaction`：

```text
response_latency_mean
response_latency_p90
response_rate
yield_latency_mean
yield_rate
agent_interruption_event_rate
agent_interrupted_turn_rate
speech_overlap_duration
on_time_rate
selectivity_backchannel
selectivity_vocal_tic
selectivity_non_directed
```

通话级 selectivity 标记沿用现有输出用途，说明它是三项错误数量的派生标记。

以下保留在评测日志或明细：

- 正式发言和用户独立事件数量、类型、ID。
- 每次正式发言的响应记录。
- 每次插话的停声候选、确认、延迟和观察不足原因。
- 打断事件数、被打断轮次数及关联 ID。
- 每次正式发言的重叠秒数。
- 工具上下文和及时上限。
- 各指标适用题目数、试验数、事件数。
- 声音检测配置、时间来源、指标版本和汇总规则。

这些明细用于解释结果，不增加新的 Agent 性能评分。

## 11. 代码组织

建议新增一个职责集中的模块，例如 `src/tau2/metrics/voice_interaction.py`，处理发言分组、响应／让话／打断事件、指标和汇总。

现有 `src/tau2/voice/audio_activity.py` 继续负责公共声音证据。用户事件分类在模拟器和独立事件产生位置完成，沿现有日志传递。

统一模块只读取已记录事实，不调用 API，不改变待测 Agent 的内部策略，不建设通用规则引擎。

| 代码区域 | 修改内容 |
| --- | --- |
| 用户模拟器、音频分块、独立音效生成位置 | 保留正式发言与各类独立事件的用途、ID、实际范围 |

实际修改按调用关系收敛，不要求每个文件都大改。

## 12. 实施顺序

### 第一步：补齐用户事件用途

在生成位置标记正式发言、附和、独立音效、环境音频及控制事件。沿实际发送过程保存，不从最终转写猜分类。

产出：可以直接建立分母的正式发言列表及 selectivity 所需独立事件。

### 第二步：构造统一时间输入

读取用户实际范围、Agent 原始有声区间，建立 200 毫秒发言分组，同时保留原始区间。

产出：响应、重叠、停声和新开口计算共用的输入。

### 第三步：实现响应记录

每次正式发言建立唯一记录，处理 0 秒响应、后续首次发声、下一次正式发言截止和未响应。

产出：响应率、平均延迟、P90、On Time Rate 共用的样本。

### 第四步：实现 1 秒停声确认

实现候选停声、恢复发声、确认停声以及通话末尾观察不足。移除正式让话的 2 秒期限。

产出：让话与 selectivity 共用的停止证据。

### 第五步：接入打断和重叠

按新发言分组生成 Agent 主动打断事件；按原始声音计算实际重叠。统一正式发言分母。

产出：两种打断率及平均重叠时长。

### 第六步：接入三项 selectivity

使用用户事件类别、公共声音状态和停声确认，保留各自观察范围。通话标记从相同错误记录派生。

产出：完整 12 项主要语音指标及通话派生标记。

### 第七步：统一汇总和出口

## 14. 轻量验证

测试放在开发测试中，只覆盖容易算错的机制：

1. 正式发言进入分母，独立附和、噪声与控制信号不进入。
2. 正式发言中的口头语或背景声不改变整次发言分类。
3. 用户结束时 Agent 持续发声，不算响应；只有用户结束后新发言分组才产生响应。
4. 多段回答不会让一次正式发言重复进入分子，独立事件不错误关闭响应窗口。
5. 200 毫秒分组与 1 秒停声确认分别工作，确认等待不加入让话延迟。
6. 没有及时期限时，较晚的确认停声仍能形成让话记录；末尾不足 1 秒记录观察不足。
7. 同一轮多次主动打断，事件率与轮次率分别计数。
8. 重叠只计算真实声音；只有用户结束时新发言分组恰好开始的 0 秒响应属于及时响应。
9. 三项 selectivity 共用停止判断，保留事件类别与观察范围。
10. 不同题目的事件数和试验数不同，普通汇总与加权 P90 仍满足题目等权。

优先扩展已有相关测试，不建设大规模测试矩阵，不调用模型 API，不要求全数据集评测。

不新增运行前验收、每轮校验、评分后审计、双版本评分或自动重跑。分子不超过分母由“每次正式发言只有一条响应记录”自然保证；各指标一致性由共同事件来源保证。

## 15. 完成后的预期结果

新语音评测只有一套正式发言列表、一套响应关联、一套停声确认和一套 Agent 主动打断事件。各指标从共同记录派生，按统一题目权重汇总。

持续旧发言不对应响应；正式让话只记录是否发生及实际延迟，不再设置及时期限；三项 selectivity 采用同样的 1 秒停声确认；两种 Agent 打断指标同时保留。

P90 的题目等权加权方案已确认。本轮讨论没有遗留需要重新选择的核心指标规则，具体代码结构和边界实现按本计划推进。
