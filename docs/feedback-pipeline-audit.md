# 反馈评测链路审计

审计对象：Qwen Audio Agent 的播放适配器、共享音频缓冲、转写分组、diagnostics 证据采集、文本评分消费者与结果版本标识。此次审计针对“5 题仅有 1 个可评分窗口”的异常展开，不是对所有音频供应商或全部 LLM 语义判断的可靠性证明。

## 已证实的问题与修复

### 1. 无效 clear 通知被当成截断

Qwen 适配器此前收到 `clear` 就无条件设置 `was_truncated`，即使没有待播音频，或指定回复已经完整播放。共享转写又把事件挂到最近开始过的一段语音上，没有检查它是否早已结束。

这批真实记录中，有 62 个事件被挂到已经结束 2.04–32.59 秒的发言上，涉及 60 段发言。事件的 `truncated_audio_bytes` 都是 0。零丢弃字节本身不是没有截断的证明；本次误归属判断同时依赖已记录的语音结束时间和事件间的较长静音。

修复分为两层：

- 上游将清空通知分为取消活动回复、回复早已完成、没有待播内容，记录 response ID 及已接收、已播放、已丢弃字节数。无效清空不再触发截断布尔值。
- 下游优先按取消的 response ID 归属到实际播放的回复；新回复不会继承旧回复的截断。历史记录没有 response 级证据时，仅在语音覆盖的 tick 或紧接的下一个 tick 内按时间归属，不再将很晚的事件回挂。

历史布尔标记仍不能恢复完整的远端取消语义。后续新运行使用更完整的 response 级记录，历史结果需要保留版本与证据限制。

### 2. 取消旧回复会连带丢弃新回复尾部

同一 tick 内可能既取消旧回复，又收到新回复音频。适配器虽已按回复删除旧音频，共享缓冲却看到全局 `was_truncated=true`，继续丢弃所有剩余音频，连新回复的待播尾部也被删除。

这是实际播放流程的问题，已用无需 API 的测试复现；不能仅凭旧通话的播放后录音判断历史发生次数。

修复后，适配器明确标记已完成 response 级过滤，缓冲只对留下的音频做正常逐 tick 播放。测试覆盖两种到达顺序、已完成回复的迟到 clear，并核对每个回复“接收字节 = 播放字节 + 取消丢弃字节”的守恒关系。

### 3. 有语音但没有转写会被静默忽略

采集器原来遇到没有文字的语音组直接跳过。异步 ASR 尚未完成、末尾转写缺失等情况因此可能看起来像 Agent 没有说话。

现在为这类已记录语音保留 unavailable 占位，传递音频与文本无法对齐的原因。精简反馈拒绝不完整证据；纯查询执行诊断在转写缺失时返回未知；原始 COMMUNICATE/NL 文本评分在语音无法对齐时拒绝评分，避免把采集故障直接写成业务失败。真正 `complete=false` 的回复仍按用户确认的规则忽略或排除，未放宽。

### 4. 运行/评分指纹没有完整覆盖播放和转写代码

原先的 Gaia2 runtime pin 没有覆盖 Qwen tick 适配器、共享缓冲及部分转写代码；diagnostics 的实现哈希也没有覆盖共享转写目录。修复这些代码后，可能未正确触发运行校验或评分缓存失效。

现已补入依赖路径，并增加模拟源代码变化的指纹回归测试。后续运行必须使用通过参考验证重新封存的绑定；旧轨迹与旧评分不自动改写。

## 真实轨迹核查

对 `concise-feedback-real-five-20261107-222508` 中的 5 道真实题目核查了：

- 诊断音频与独立录音 tap：将双方 μ-law 诊断音频解码为 PCM 后，与独立的 Agent 输出和实际 Agent 输入录音逐字节比较，10 个声道全部一致。
- 媒体包 offset 连续，每包长度与记录一致，没有发现诊断采集阶段的字节丢失或重复。这不能证明采集之前没有因旧缓冲错误丢弃音频。
- 重新构造 Agent 完整性标记时，文字、时间、阶段和 ID 保持一致；用户证据保持原样，原始数据哈希未变。
- 另外检查原始 Gateway trace 的全部 67 个 clear：此前已接收音频的回复在 clear 前均有 audio_done。audio_done 单独不能证明队列播完，但结合零丢弃字节和播放时间，进一步支持此次误标结论。
- 修复后的同批预检有 13/15 个可评分窗口。0251 的另两窗仍因用户侧不完整话语而排除。预检数量不代表已完成新的 LLM 评分。

审计原始记录：`data/simulations/concise-feedback-real-five-20261107-222508/truncation-audit/` 下的 `pipeline-audit.json`、`audio-integrity.json`、`reprojection.json`、参考验证日志及 provider suite 记录。

## 验证边界

- 整链路回归 443 项通过，Gaia2 场景回归 71 项通过，完整 voice/streaming 离线测试 713 项通过、3 项跳过、138 项未选择；这些测试集合存在重叠，不相加为一个总数。
- 1000/1000 题完成原生参考执行和严格重放并重新封存；确认业务题目内容完全不变，仅更新运行/资源绑定字段。共执行 15,973 条 authoring 检查，其中原始题 0031 的 4 条结果断言未通过，完整错误保留在 `reference-summary.json`，未将其当作通过。
- 离线回归覆盖实际截断、空清空、迟到清空、取消与新音频同 tick、延迟转写、缺少转写、评分未知值、缓存和运行指纹。
- provider suite 保留 live gates；没有因本次审计自动访问其他供应商。跳过的 live 测试不能算作通过。
- 全量 Gaia2 参考执行/重放检验工具与场景一致性，不证明 ASR 或 LLM Judge 的语义正确性。reference-summary.json 同时记录 reference 结果和未通过的 authoring 断言，两者不混淆。
- 分段 ASR 没有词级强制对齐，语言识别、姓名数字识别和混合语言转写仍需独立听评。字节一致并不意味着转写一定正确。
- 本次没有新跑真实 Agent 通话，也没有调用 LLM 重算旧评分。旧的有效率、纯查询执行诊断及截断相关分数应按旧实现版本解释；重新评分需使用明确记录来源的修复后证据。

应将结论表述为“已修复并验证上述明确缺陷”，不能表述为“整个 Benchmark 已被证明完全没有问题”。
